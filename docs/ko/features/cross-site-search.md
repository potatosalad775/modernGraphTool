내 사이트의 검색창에서 다른 측정 데이터베이스의 기기까지 함께 검색합니다. 결과를 누르면 해당 사이트로
바로 이동하며, 기기가 로드된 상태로 열립니다.

## 개요

방문자가 내 사이트에 없는 기기를 검색하면, 그 기기를 보유한 다른 데이터베이스를 알려줍니다.
내 검색 결과 아래에 다른 공개 측정 데이터베이스의 결과가 사이트와 리그(rig) 종류별로 묶여 표시됩니다.

이 기능은 **호스팅 환경과 무관하게** 동작합니다. squig.link가 아니어도 됩니다. 미리 만들어진 단일 인덱스
문서를 읽기 때문에, 등록된 데이터베이스가 몇 개든 요청은 한 번뿐입니다.

인덱스는 [GraphAggregator](https://github.com/HarutoHiroki/GraphAggregator)에서 제공합니다.
알려진 측정 데이터베이스를 수집해 기기 목록을 하나의 JSON 파일로 발행하는 커뮤니티 프로젝트입니다.
modernGraphTool에 공식 URL이 내장되어 있어 따로 설정할 것은 없습니다.

## 쉼표로 구분한 검색어

`hd 600, u12t`처럼 입력하면 질문이 달라집니다. *이 둘을 **모두** 가진 데이터베이스가 어디인가?* 모든
검색어에 대해 일치하는 기기를 가진 데이터베이스만 목록에 나타나며, 각 사이트는 일치하는 기기를 모두 보여줍니다.
두 기기를 비교하려는 방문자가 서로 다른 사이트의 그래프를 짜맞추는 대신, 둘 다 같은 리그(rig)로 측정한 사이트를 찾을 수
있습니다.

검색창 옆의 **i** 버튼을 누르면 이 팁들이 UI에 표시되므로, 방문자가 문법을 짐작할 필요가 없습니다.

각 검색어는 두 글자 이상이 되어야 적용됩니다. 둘째 검색어를 입력하는 도중에 결과가 요동치지 않도록 하기 위함입니다.
맨 뒤에 남은 쉼표는 무시됩니다.

내 사이트의 기기 목록도 같은 검색어를 읽지만, 여기서는 검색어를 합집합니다. 한 기기가 동시에 둘 다일 수는 없으므로,
둘 중 하나라도 일치하는 기기를 모두 보여 함께 로드할 수 있게 합니다.

## 다른 표기 함께 검색하기

같은 모델이라도 데이터베이스마다 표기가 다른 경우가 많습니다. 어떤 사이트에서는 `Lyro`, 다른 사이트에서는
`Lyrö`처럼요. 표기를 슬래시 두 개로 구분하면 그중 하나라도 일치하는 기기를 찾습니다. `lyro // lyrö`는 둘 중
어느 표기든 가진 데이터베이스를 모두 보여줍니다.

`//`는 쉼표보다 먼저 묶입니다. 쉼표로 나뉜 각 그룹이 기기 하나이고, 그 안의 `//` 대안은 같은 기기의 다른
이름입니다. `lyro // lyrö, hd 600`은 HD 600과, 두 표기 중 하나의 Lyro를 *함께* 가진 데이터베이스를 보여줍니다.

슬래시 하나는 여전히 검색어의 일부입니다. `16/Cosmos`, `HD650/HD6XX`처럼 슬래시 하나가 들어간 기기 이름은
많지만, 두 개가 들어간 이름은 없습니다.

## 특정 단어 제외하기

이름이 더 큰 제품군과 겹치는 모델은 따로 찾기 어렵습니다. `earphones`를 검색하면 Earphones Pro, Plus, Max까지
함께 나오니까요. 단어 앞에 `-`를 붙이면 그 단어가 들어간 기기를 모두 제외합니다. `earphones -pro -plus -max`는
기본 Earphones만 보여줍니다.

- 제외는 **단어 단위**로 일치합니다. `-pro`는 `Earphones Pro`는 제외하지만 `Prodigy`는 남겨 둡니다.
- 제외는 자신이 속한 쉼표 그룹에만, 그 그룹의 `//` 대안까지 포함해 적용됩니다. `lyro // lyrö -mk2, hd 600`은
  두 표기 모두에서 Lyro MK2를 제외하고, HD 600 쪽에는 영향을 주지 않습니다.
- 단어 맨 앞의 `-`만 제외로 인식합니다. `HE-400se`는 입력한 그대로 검색되며, 양옆에 공백이 있는 `-`도
  마찬가지입니다.
- `-pro`처럼 제외만으로 이루어진 그룹은 기기를 가리키지 않으므로 무시됩니다.
- 검색어와 달리, 제외는 첫 글자부터 바로 적용됩니다.

`Ocean (Reference Nozzle -6dB Bass)`처럼 단어 자체가 `-`로 시작하는 기기 이름도 몇 개 있습니다. 이런 기기는
`-` 없이 검색하세요. `nozzle 6db`로도 찾을 수 있습니다.

## 설정

`config.js`에서 설정합니다.

```javascript
CROSS_SITE_SEARCH: {
    ENABLED: true,
    INDEX_URLS: [],
}
```

### 설정 옵션

- **`ENABLED`** — 크로스 사이트 검색 켜기/끄기. 기본값은 켜짐.
- **`INDEX_URLS`** — 시도할 인덱스 문서 목록(순서대로). 비워 두면 공식 GraphAggregator 인덱스를
  사용하며, GitHub Pages 미러가 자동 백업으로 동작합니다.

## 인덱스 직접 호스팅하기

외부 도메인에 의존하고 싶지 않다면, 인덱스 문서를 직접 발행하고 `INDEX_URLS`를 그쪽으로 지정하세요.

```javascript
CROSS_SITE_SEARCH: {
    ENABLED: true,
    INDEX_URLS: [
        'https://example.com/my-index.json',
        'https://backup.example.com/my-index.json'
    ],
}
```

URL은 순서대로 시도하며 유효한 문서를 먼저 반환한 쪽이 채택됩니다. 따라서 미러를 백업으로 함께 적어 둘 수
있습니다. 문서는 GraphAggregator 스키마를 따라야 합니다. 명세와 생성 도구는
[GraphAggregator 저장소](https://github.com/HarutoHiroki/GraphAggregator)를 참고하세요.

## 참고

- 방문자가 현재 보고 있는 사이트의 데이터베이스는 결과에서 제외됩니다.
- 검색 결과는 한 번에 최대 100개까지 표시됩니다. 더 많이 일치하면 검색어를 좁히라는 안내가 나타납니다.
- 인덱스는 방문자가 두 글자 이상 입력한 시점에 처음 한 번만 지연 로드됩니다. 검색하지 않는 방문자에게는
  아무 비용도 발생하지 않습니다.
