Testing

modernGraphTool uses Vitest with Playwright browser mode. Specs are co-located next to the code they cover as *.spec.ts.

Running tests

Section titled “Running tests”
CommandWhat it does
npm run testFull suite — both the client and server projects
npm run test:unitSame suite in watch mode
npm run test:coverageFull suite + v8 coverage report into coverage/
npm run test:smokeBoots the built dist/ in three engines (build first)

The two projects

Section titled “The two projects”

The filename decides which project runs a spec:

  • *.svelte.spec.ts → the client project, in real Chromium via Playwright
  • everything else → the server project, in node

Most specs drive stores and services directly. Component specs mount with render() from vitest-browser-svelte and query through page.getBy* from vitest/browser.

Where the gotchas are documented

Layer-specific testing traps live next to the code, in per-directory AGENTS.md files — component and boot-test traps in src/lib/components/, d3/rAF traps in src/lib/graph/, and the connect-flow mocking pattern in src/lib/device-peq/. They are kept there rather than here so they stay accurate as the code moves.

Property-based tests

Section titled “Property-based tests”

Code that reads text anyone can send (a share link, a phone_book.json description) also has properties checked on generated input, with fast-check. They live in *.property.spec.ts files, such as src/lib/utils/untrusted-input.property.spec.ts: a decoder never throws, a query decodes back to the names it was built from, and sanitizing twice changes nothing.

The input is random, so a failure prints a seed and a shrunk counterexample. Reproduce it by passing that seed as fc.assert(property, { seed }), and treat it as a real bug until you have shown that the property is wrong. When you add a property, break the code it guards on purpose and confirm that it fails.

Coverage

Section titled “Coverage”

The configuration lives in vite.config.ts under test.coverage, and two settings there are load-bearing:

  • The include glob covering all of src is what makes files that no test imports count at all. Without it an untested module vanishes from the denominator rather than showing as the 0% it is — the ~25 device handler and connector modules that lived in device-peq/ before the eqcaps bridge replaced them made the reported number about 10 points optimistic that way. (Vitest 4 removed the old coverage.all flag — include now does that job, and passing all is a type error.)
  • exclude omits the Paraglide output. src/lib/paraglide/ is generated by the Paraglide Vite plugin and is gitignored; counting it added ~3800 machine-written statements — a third of the total — and dragged the figure well below what the hand-written source actually is. src/lib/types/** (type-only) and src/routes/** (shells covered by the boot tests) are excluded for the same “not meaningfully coverable” reason.

thresholds is a ratchet, not a target

It holds the measured numbers as of the last improvement. Raise it when coverage goes up; never lower it to turn a red run green. CI runs coverage on the Linux leg only, and it blocks — a PR that falls below the ratchet has removed coverage that used to exist.

Smoke test

Section titled “Smoke test”

The unit suite mounts components against source, so nothing in it ever loads what the build emits. An adapter-static misconfiguration, a defaults/ file the Vite plugin stopped copying, an asset-URL regression, or a worker that fails to resolve once bundled will all ship a blank page with the whole suite green.

scripts/smoke-dist.js serves dist/ over real HTTP — including the SPA fallback that .htaccess provides — boots it in Chromium, WebKit and Firefox through Playwright, and fails on a console error, an uncaught exception, a 4xx, a graph that never draws, or a ?share= link that lands no curve. It sends the recommended security headers with Trusted Types on, and checks that each engine enforces them. It also runs AutoEQ, which fails if the worker never answers or the wasm engine fell back, and opens the tooltip of a disabled button.

It is the only test that leaves Chromium: the component specs run in Chromium alone. Install the other two engines once with npx playwright install webkit firefox, or run a single engine with npm run test:smoke -- --browser firefox.

WebKit is not Safari

Playwright’s WebKit is close to desktop Safari, not identical, and shows no iOS-only behavior. A pass there does not replace a check on a real iPhone. WebHID and Web Bluetooth exist only in Chromium, so the Hardware EQ paths are single-engine whatever the test says.

Three things to keep in mind when extending it:

  • A check that cannot apply to an engine is skipped for that engine, with the reason written next to the skip. None is skipped today.
  • A 200 does not prove a file exists. The SPA fallback answers anything not on disk with index.html, on the real Apache host as much as here, so asset checks compare the body against the HTML shell rather than trusting the status.
  • It runs in its own smoke CI job, which builds the app first because the test needs the built output. The job runs in Playwright’s Docker image, which ships the three engines. The image tag must match the playwright version in package-lock.json, and the job fails with the tag to set when it does not.

Continuous integration

Section titled “Continuous integration”

.github/workflows/ci.yml runs on every PR and every push to main: lint → check → test on ubuntu-latest, plus a build of the app, the smoke test in three browser engines, the CDN distribution and the docs site. CI tests across browser engines, not operating systems.

A Windows leg remains for line endings only: it installs, lints and checks the tree, and runs no typecheck and no tests. Git for Windows sets core.autocrlf=true in its system config, so before .gitattributes pinned every text file to eol=lf, the same commit was Prettier-clean on macOS and dirty on Windows. The lint step and the Working tree must be clean step guard against that regressing: the second fails if a checkout plus install leaves anything modified, or if CRLF ever reaches the index or the working tree.

npm run lint must exit 0, and an ESLint warning fails it like an error (--max-warnings 0). Rule overrides live in eslint.config.js and each carries a comment explaining why — notably no-useless-assignment is off for *.svelte because it misreads $bindable() prop defaults, and no-explicit-any is off under docs/ because the config migration tool parses arbitrary operator-authored config.

In src/, two type-aware rules hold app code to its types. no-unnecessary-condition fails a guard the types say can never fire, so a value from outside them (operator config, fetched JSON, storage, a DOM read, an index that can miss) is typed | undefined where it enters, and its guard stays. no-non-null-assertion fails a !: narrow instead, or throw where absence is a bug. Specs and test fixtures may still use !.

App code outside the specs is also held to typescript-eslint’s strict-type-checked and stylistic-type-checked presets, and to a complexity limit of 15 per function. Nothing is suppressed in bulk: never run eslint --suppress-all to make a red lint pass. A function over the limit is split, with its spec as the pin.

Two helpers in src/lib/utils/ exist for these presets. track(a, b) names the reactive values an $effect depends on without otherwise using (a bare void a; fails no-meaningless-void-operator). noop fills a callback slot that needs no action, such as .catch(noop) on a rejection that is safe to ignore (an empty arrow function fails no-empty-function).
