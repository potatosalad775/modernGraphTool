Device PEQ는 DAC, 동글, 스트리머, 일부 헤드폰 같은 지원 기기의 파라메트릭 EQ를 브라우저에서 바로 읽고 쓰는 기능입니다. 별도 소프트웨어는 필요 없습니다. 한 번 기록한 EQ는 기기 자체 메모리에 저장되므로 컴퓨터에서 분리해도 계속 적용됩니다.

Equalizer 패널 맨 아래에 있습니다. 사용 흐름은 [오디오 이퀄라이징](../guide-for-users/equalizing.mdx#device-peq)을 참고하세요.

## 연결하기

대부분의 동글과 DAC는 **Connect USB device**로 연결합니다. 다른 연결 방식은 그 바로 아래에 있습니다.

| 연결 방식      | 브라우저 API  | 예시                                              |
| -------------- | ------------- | ------------------------------------------------- |
| **USB**        | WebHID        | FiiO, Moondrop, Walkplay, KT Micro 동글, DAC/앰프 |
| **USB serial** | Web Serial    | JDS Labs, Nothing, FiiO, 블루투스 시리얼 포트     |
| **Bluetooth**  | Web Bluetooth | 일부 FiiO 및 Airoha 칩셋 기기                     |
| **Network**    | —             | WiiM 스트리머, Luxsin X9 같은 IP 주소 기반 기기   |

브라우저의 기기 선택 창에는 Device PEQ가 다룰 수 있는 기기만 표시됩니다. 기기를 고르면 [eqcaps](https://github.com/potatosalad775/eqcaps)에서 해당 기기를 찾습니다. eqcaps는 각 EQ 엔진이 받아들이는 값 — 밴드 수, 밴드별 필터 종류, 주파수·Q·게인 범위와 단위, 프리앰프 — 과 통신 방법을 담은 공개 데이터베이스입니다.

- **여러 기기가 해당될 때.** 같은 식별 정보를 보고하는 기기가 있습니다(블루투스 시리얼 포트는 기기 이름조차 알려주지 않습니다). 이럴 때는 어떤 기기인지 묻습니다.
- **공용 프로필.** 칩셋 펌웨어를 공유하는 기기 묶음으로만 알려진 기기도 있습니다. 이 경우 정확한 모델이 목록에 없다고 안내하며, 묶음의 제약 조건이 그대로 적용됩니다.
- **데이터베이스에 없을 때.** 알려진 제조사의 기기라면 그 제조사의 일반적인 프로토콜로 연결하고, 프로토콜이 전달할 수 있는 범위를 제약 조건으로 사용하며 실험적 기능으로 표시합니다. 다룰 수 없는 기기에는 [eqcaps inspector](https://potatosalad775.github.io/eqcaps/connect)로 가는 **Help add it** 링크가 표시됩니다. inspector에서 연결한 기기를 데이터베이스 항목으로 만들 수 있습니다.

최신 지원 기기 목록은 패널 안의 **About Device PEQ** 대화상자(**New to Device PEQ?**)에서 확인할 수 있습니다.

## 기기의 제약 조건

기기가 연결되어 있는 동안에는 기기의 제약 조건이 활성 [EQ 제약 조건](./equalizer.mdx#eq-constraints)이 됩니다. 연결만으로 밴드가 바뀌지는 않습니다. 기기가 담을 수 없는 밴드는 표시만 되고, 밴드 목록 위의 **Fit**을 누르면 기기가 받아들이는 가장 가까운 값으로 한 번에 옮겨집니다(실행 취소 가능). 그 뒤로는 직접 편집이나 AutoEQ도 제약 조건 안에서 이루어집니다. 5밴드 기기에서는 AutoEQ도 5밴드로 계산합니다. 연결을 끊으면 이전에 고른 제약 조건으로 돌아갑니다.

아직 실제 기기로 확인하지 않은 프로필에는 그 사실과 함께 **Report wrong limits** 링크가 표시됩니다.

## 읽기와 쓰기

- **Read from device** 는 기기의 EQ를 밴드 목록으로 불러오고 Equalizer를 켭니다. 프리셋이 여러 개인 기기는 **Preset** 에서 고른 프리셋을 읽습니다.
- **Write to device** 는 밴드 목록을 기기에 보냅니다. 범위를 넘는 게인, 기기의 단위로 표현할 수 없는 값, 기기보다 많은 밴드처럼 기기가 그대로 담을 수 없는 부분이 있으면, 무엇이 바뀌는지 밴드별로 먼저 보여 주고 확인을 받은 뒤에만 기록합니다. 사용하지 않는 밴드는 평탄하게 기록됩니다.
- **Device EQ** 는 기기에 EQ 스위치가 있을 때 기기의 EQ를 끄고 켭니다. 프리셋을 고르는 것만으로는 기기에 아무것도 기록되지 않습니다.

저장할 때 재시작하는 기기도 있습니다. 그러면 패널에 **Reconnect** 가 나타나며, 브라우저의 선택 창 없이 같은 기기를 다시 찾습니다.

프리앰프는 프리앰프를 받는 기기에만 보냅니다. 레벨을 스스로 낮출 수 없는 기기에 부스트가 있는 EQ를 보내면 클리핑 경고가 표시됩니다.

:::note[공용 밴드만 전송]
하드웨어 EQ 슬롯에는 채널 개념이 없습니다. 쓰기는 **L+R** 밴드만 전송하고, 건너뛴 좌·우 전용 밴드가 몇 개인지 알려 줍니다. [채널별 EQ](./equalizer.mdx#per-channel-eq)를 참고하세요.
:::

## 브라우저 지원

Device PEQ는 **Chrome, Edge, Opera** 같은 Chromium 기반 브라우저에서만 동작합니다. Firefox와 Safari는 WebHID, Web Serial, Web Bluetooth를 모두 지원하지 않으므로, 연결 버튼 대신 호환성 안내가 표시됩니다.

## 운영자

기기 데이터베이스는 GitHub Pages의 eqcaps `/v1/` 채널에서 읽어옵니다. `EQUALIZER.EQCAPS_URL` 로 미러나 직접 호스팅한 사본을 지정할 수 있습니다. [페이지 커스터마이징](../guide-for-admins/customize-page.mdx#equalizer)을 참고하세요. 데이터베이스에 접근할 수 없어도 알려진 제조사의 기기는 프로토콜 자체의 범위로 연결됩니다.

## 감사의 말

기기 프로토콜은 eqcaps device bridge를 거쳐 [jeromeof의 devicePEQ 프로젝트](https://github.com/jeromeof/devicePEQ)(0BSD 라이선스)에서 가져왔습니다.
